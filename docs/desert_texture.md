# How the desert ground textures were made

A recipe for re-creating Dorkfall's two desert grounds. It is written so another Claude chat can
implement them from scratch, in this project or another one.

1. **Sand desert**: pale sand in soft flat patches, with dune ripples and a dithered edge where it meets grass.
2. **Red clay** (the ravine floor): dark red clay in flat patches with a network of dried-mud cracks and a few stones.

Both are generated by a Python script (numpy + Pillow) that paints straight into the ground
image. They are not tiles and not shaders. The real scripts are `tools/gen_desert.py` (the west sand desert)
and `tools/gen_ravine.py` (the clay, the mountains and ravine, and the east desert past the pass;
its `desert()` function repeats the sand recipe below for that area). This file explains the method and gives
self-contained code.

---

## 0. Ground rules (read first)

- **Pixel scale:** the ground art is drawn at 2 art pixels per world pixel. The game viewport is
  640x360 at camera zoom 2, so **1 art pixel = 1 screen pixel**. Every size below is in art
  pixels unless it says "world px".
- **Style:** flat colour areas (3-4 tones), no smooth gradients, no blur. Variation comes from
  *where* each tone goes, never from blending colours.
- **Randomness:** one seeded generator (`np.random.default_rng(SEED)`), so re-running gives the
  same picture.
- **Work on a copy:** the script reads the original ground, paints the new area and writes the
  result. If you will tweak and re-run, keep a backup of the untouched ground and start from it
  each time. Otherwise each run paints over the last.
- **Protect what shouldn't change.** Build a mask of pixels that may be repainted, for example
  "grass-coloured pixels, but not roads or stone". Only paint inside it (see `replaceable()` below).
- **Keep everything on the pixel grid.** The edges use single-pixel dithering, which flickers if
  the camera stops between pixels. Dorkfall turns on `snap_2d_transforms_to_pixel` on the game's
  SubViewport (`scenes/game.tscn`), which snaps every sprite to whole world px, and rounds the
  camera to whole world px too (`Player._place_camera()` in `scripts/player.gd`), so the camera
  and the sprites always agree. Movement stays smooth because the player is drawn with physics
  interpolation. (Rounding the camera to half world px instead made it disagree with the snapped
  sprites: the player wobbled. Turning the snap off made moving sprites look blurry.)

## 1. The two building blocks

### Blobby noise: soft patches, values 0..1
Small random grids blown up with bicubic resizing and added together at a few sizes. `cell` is
roughly the patch size in art pixels.

```python
import numpy as np
from PIL import Image

rng = np.random.default_rng(7)

def smooth_noise(w, h, cell, octaves=3):
    out = np.zeros((h, w), np.float32)
    amp, total = 1.0, 0.0
    for o in range(octaves):
        c = max(int(cell / (2 ** o)), 4)
        gw, gh = w // c + 3, h // c + 3
        grid = Image.fromarray((rng.random((gh, gw)) * 255).astype(np.uint8))
        big = grid.resize((gw * c, gh * c), Image.BICUBIC)
        out += np.asarray(big, np.float32)[:h, :w] / 255.0 * amp
        total += amp
        amp *= 0.5
    return out / total
```

Turning noise into flat tones is the key trick: `np.digitize(noise, [t1, t2])` gives 0/1/2 per
pixel, and you index a palette with it. That produces the flat patch shapes of pixel art.

### Cell pattern (Voronoi): for cracks and stones
It scatters one random point per grid cell. For every pixel it reports how close the pixel is to
the border between its cell and the next one (`edge`), and where it sits inside its own cell
(`rx`, `ry`, from -1 to 1). Cracks are the pixels with `edge < 1.6`. Stones use `rx` and `ry`
to shade a light top and a dark side.

```python
_TAB = rng.random((2, 512)).astype(np.float32)

def voronoi(x, y, cw, ch):
    """x, y: arrays of pixel coordinates; cw, ch: cell size. Returns (edge, rx, ry)."""
    ix, iy = np.floor(x / cw).astype(np.int64), np.floor(y / ch).astype(np.int64)
    best = np.full(x.shape, 1e9, np.float32); second = best.copy()
    bx = np.zeros(x.shape, np.float32); by = bx.copy()
    for dy in (-1, 0, 1):
        for dx in (-1, 0, 1):
            cx, cy = ix + dx, iy + dy
            h = (cx * 73856093 ^ cy * 19349663) & 511
            sx = (cx + 0.15 + 0.7 * _TAB[0][h]) * cw
            sy = (cy + 0.15 + 0.7 * _TAB[1][h]) * ch
            ddx, ddy = (x - sx) / cw, (y - sy) / ch
            dist = np.sqrt(ddx * ddx + ddy * ddy) * min(cw, ch)
            closer = dist < best
            second = np.where(closer, best, np.minimum(second, dist))
            bx = np.where(closer, ddx, bx); by = np.where(closer, ddy, by)
            best = np.where(closer, dist, best)
    return second - best, bx * 2.0, by * 2.0
```

## 2. Sand desert

**Palette:** the same sand tones as the game's beach, so the two match.

| Use | RGB |
|---|---|
| Sand dark / base / light | (220,188,133) (233,207,155) (242,223,179) |
| Dune shadow | (209,174,120) |
| Specks (with how often each appears) | (192,154,108) 1.0%, (250,236,200) 0.4%, (214,128,84) 0.12%, (150,118,84) 0.15% |

**Steps** (arrays of the area's size `h x w`; `world_x` / `world_y` give each pixel's world position):

1. **Wobbly edge line.** Where grass becomes sand, the edge wanders using a few sine waves of
   different lengths:
   `edge = DESERT_X + 70 * (0.55*sin(y/180) + 0.3*sin(y/67+1.3) + 0.15*sin(y/29+4.0))`.
   Then `t = (world_x - edge) / 90`: below 0 is grass, 0..1 is the mixing band, above 1 is sand.
2. **Dithered transition** (lumpy, then speckled at the very edge, like the beach):
   ```python
   blobs = smooth_noise(w, h, 120); grain = rng.random((h, w))
   want_sand = (t + (blobs - 0.5) * 0.9 + (grain - 0.5) * 0.35) > 0.5
   tufts = smooth_noise(w, h, 40, 2)                       # a few grass tufts survive in the sand
   want_sand &= ~((tufts > 0.78) & (t < 2.2) & (grain < 0.85))
   mask = want_sand & replaceable(art, world_y)
   ```
3. **Flat sand tones:** `tone = np.digitize(smooth_noise(w, h, 90), [0.44, 0.58])`, then `sand = SAND[tone]`.
4. **Dunes:** long soft ripples with a bright crest and a shadow line, only in some areas and only deep in the sand:
   ```python
   warp = smooth_noise(w, h, 260, 2)
   ridge = np.sin((world_y + warp * 140 + np.sin(world_x / 130) * 24) / 21)
   zone = (smooth_noise(w, h, 300, 2) > 0.58) & (t > 1.5)
   sand[zone & (ridge < -0.62) & (ridge > -0.78)] = SAND_DEEP     # shadow
   sand[zone & (ridge > 0.96)] = SAND[2]                          # crest
   ```
5. **Specks:** for each speck colour, pick that share of pixels at random and paint them.
6. **Apply:** `art[mask] = sand[mask]`.

**Protect roads and stone:**
```python
def replaceable(px, world_y):
    r, g, b = (px[..., i].astype(int) for i in range(3))
    green = (g > r + 12) & (g > b + 8)
    stone = (abs(r - g) < 12) & (abs(g - b) < 14) & (r < 180)
    in_road = (world_y >= 238) & (world_y <= 274)        # the road's band: only its grass edges change
    return np.where(in_road, green, ~stone)
```

**Desert props** (separate sprites, not part of the ground): saguaro cacti, drawn by the same
script with `ImageDraw`. Each is a rounded column with a dark outline, a light stripe on the
left, a dark stripe on the right, a dark rib down the middle, optional arms joined by short
elbows, 18 random pale spine pixels and a small sand mound at the foot. Colours: outline
(34,52,34), dark (52,108,58), mid (74,142,72), light (112,178,92), spines (236,226,190).

## 3. Red clay with dried-mud cracks

**Palette:**

| Use | RGB |
|---|---|
| Clay, darkest to lightest | (96,44,34) (112,54,41) (128,64,47) (146,78,56) |
| Crack | (78,36,29) |

**Steps:**

```python
rows = np.arange(h)[:, None] + np.zeros((1, w)); cols = np.arange(w)[None, :] + np.zeros((h, 1))
tone = smooth_noise(w, h, 80)
clay = CLAY[np.digitize(tone, [0.36, 0.5, 0.64])].copy()   # 4 flat tones in blobs

edge, _, _ = voronoi(cols, rows, 34, 25)                   # mud "plates" about 34x25 px
crack_on = smooth_noise(w, h, 40) > 0.5                     # only some borders crack: open, broken network
clay[(edge < 1.6) & crack_on] = CRACK

grain = rng.random((h, w))
clay[grain > 0.994] = CLAY[0]                              # a few dark and light specks
clay[grain < 0.004] = CLAY[3]
```

Two things make the cracks look right:
- **Not every plate border cracks.** Gating by `crack_on` leaves broken, branching lines rather
  than a closed honeycomb.
- **The plates are smaller than the tone blobs** (34 px versus about 80 px). The colour patches
  and the cracks then don't line up.

**Sand-to-clay border:** a wavy line with a narrow speckled band (about 36 art px):
```python
R = smooth_noise(w, h, 24, 2); Q = smooth_noise(w, h, 110)
clay_edge = CLAY_FROM + 30*np.sin(world_y/160 + 2.0) + 12*np.sin(world_y/71 + 0.4) + 70*(Q - 0.5)
clay_t = (world_x - clay_edge) / 36 + 0.5 + 0.45*(grain - 0.5) + 0.4*(R - 0.5)
is_clay = walkable & (clay_t > 0.5)
art[is_clay] = clay[is_clay]
```
Avoid evenly spaced short sine waves for the edge (for example `sin(y/37)`). They make a
regular zigzag. Mix one long wave with noise instead.

**Stones on the clay** (optional): a second, smaller cell pattern (18x14). Use only some cells:
those where `smooth_noise(w, h, 9, 1)` is above 0.76 near cliffs and above 0.92 elsewhere. Draw
a squarish stone in each chosen cell (`max(|rx|*0.9, |ry|) < 0.6`) with a light top (ry < -0.1),
a mid front, a dark right side (rx > 0.35) and a dark rim. Rock colours: light (141,127,113),
mid (108,92,78), dark (84,69,57), rim (52,45,40).

**Shadow at a wall's foot** (optional): floor pixels up to 6 art px below a wall are multiplied by 0.8.

## 4. Checklist / pitfalls

- Never use `np.roll` to shift masks: it wraps the image around, so the left edge leaks onto
  the right. Shift with padding instead.
- Pick colours from the existing art (beach sand, rocks) so new ground matches the old.
- Keep dithering to narrow bands (edges only). Large dithered areas look noisy and shimmer in motion.
- Check in the game, not only in the PNG. Take a screenshot at 640x360 with the camera where a
  player would stand. Patch and crack sizes that look fine zoomed out can be too big or too busy at real scale.
- In Dorkfall the ground is stored as 512-world-px squares (`art/ground/g_<col>_<row>.png`).
  Use `tools/ground_tiles.py` `assemble()` to get the whole picture and `split()` to write it back.
